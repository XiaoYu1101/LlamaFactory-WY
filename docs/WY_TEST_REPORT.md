## 真实 DeepSeek 生成

使用配置文件中的 `deepseek-v4-flash`，密钥仅在本机环境使用。

| 场景 | 输入 | 请求与结果 |
| --- | --- | --- |
| 多类别、多批次 | 退款进度 1 条样例，配额 12；取消订单 2 条样例，配额 11 | 4 个批次，生成 23 条有效样本，0 重复、0 无效，数量准确 |
| Ant 页面端到端 | 发票查询 1 条样例，配额 3 | 从页面启动任务，1 个批次生成 3 条有效样本，进度自动更新，结果进入待审核列表 |

三次正式联调共新增 30 条模型样本。最新复验使用两个类别、各 1 条样例，各生成 2 条，共 4 条新增数据；0 重复、0 无效。通过 REST 接口完成查看、修改、删除、恢复、人工添加、驳回、批量通过，最终导出 6 条已通过样本（包含 2 条原始样例）。原始种子另计。测试内容为虚构客服表达；生成成功和格式校验通过不代表模型标签准确率，需要人工检查。

真实数据与日志位于被 Git 忽略的本机 `workspace/live-api-check/`，不随源码发布。仓库不包含 API 密钥。

最新独立复验记录保存在本机临时目录 `wy-acceptance-20260909-181150-c_m3nz13/acceptance-result.json`，不影响页面中的既有项目。

## 微调与结果代码复查

根据用户要求，后两项只做代码检查，不运行真实微调或评测。新增 7 项检查直接使用原有组件、参数解析和监控函数的源码，替换硬件探测及进程对象，并禁止启动真实训练进程。

- 修复快捷微调参数未同步到原 Train 页的问题；模型、LoRA、数据目录、数据集和输出目录会同步显示，训练进度及损失仍输出到原组件。
- 将日志上报配置改为原单选下拉框接受的字符串，避免恢复页面时值类型不匹配。
- 配置同步和恢复不再触发训练阶段切换时的清空数据集操作，用户主动切换训练阶段仍会清空。
- 检查原评测参数会使用选定的微调适配器和独立评测数据。
- 修复取消评测时仍读取结果文件、以及结果文件缺失或损坏时未清理运行状态的问题；这些情况会正确结束监控并恢复可用状态。

这组检查验证接口与状态逻辑，不代表目标机器的模型、GPU 或训练数值结果已经通过验证。
