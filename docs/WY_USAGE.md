# JSON 样例扩写工作台

## 工作方式

一个“生成场景”代表一项数据扩写任务。例如 `dam_intent` 是大坝监测数据场景的标识，**不是模型的输出标签**。把完整 JSON 样例交给模型，按相同字段结构扩写，再审核、导出、微调。`system`、`instruction`、`input`、`output` 只是常见字段组合，并非必需的固定格式。

支持 JSON 数组、单个 JSON 对象和 JSONL（每行一个对象）。扩展名是 `.json` 的 JSONL 也支持。可以粘贴内容，也可以在浏览器选择外部文件；原文件无需放入仓库或修改，只有配置中的样例保存在本地工作区数据库中。

每条记录必须是非空 JSON 对象。同一场景按第一条样例确定字段和类型，后续样例、生成结果及人工修改均需匹配；不同结构请分别建立场景。支持字符串（包括空字符串）、数字、布尔、null、嵌套对象和数组。数组长度可变化，元素结构需符合参考；空数组样例只能生成空数组。字段名最长 128 字符、字符串最长 16000 字符、嵌套最多 12 层、单条最多 64 KB；每个场景需提供 4 到 100 条不同的参考样例、总大小不超过 256 KB；编辑过程中允许先输入少量样例，但不足 4 条时不能保存场景或开始生成。

生成时保留参考样例中的 `system`、`instruction`、`system_prompt` 和系统对话消息原文，并保持它们的对应关系；自定义映射为 system 的字段也会保留。其他字段按业务要求扩写。格式校验不等于答案正确，仍需审核。

## 启动

Python 3.11 以上：

```powershell
python -m venv .venv-workbench
.\.venv-workbench\Scripts\python.exe -m pip install -r requirements/intent.txt
.\.venv-workbench\Scripts\python.exe scripts/intent_workbench.py
```

访问 http://127.0.0.1:7861/intent/ 。前端构建文件随源码提供，无需本机模型即可运行配置、生成、审核和导出。数据保存在 `workspace/intent/`。同一工作区只能由一个服务进程使用。

生成服务优先从系统环境变量和项目根目录 `.env` 读取，未设置的选项回退到 `config/intent_generation.json`。程序不读取 `.env.local`。

本机或局域网部署的 Qwen 只需提供兼容 Chat Completions API 的服务地址。例如：

```dotenv
WY_INTENT_BASE_URL=http://127.0.0.1:8000/v1
WY_INTENT_MODEL=auto
WY_INTENT_API_KEY=
WY_INTENT_JSON_MODE=false
WY_INTENT_THINKING=null
```

端口与地址应换成你实际启动的服务。模型在另一台机器时，将 127.0.0.1 换成那台机器的局域网 IP。这只是连接已部署模型的配置，不会自动部署或加载本地权重文件。

- 模型名为空或 `auto`：在开始生成前请求服务的 `/models`，只有一个模型时自动使用服务返回的完整 id，并写入任务元数据；有多个模型时提示明确选择，不猜测 Qwen 版本。
- 页面左下角“生成服务配置”提供“检测服务模型”，可查看服务返回的完整名称；需要指定时把它复制到 `WY_INTENT_MODEL`。
- 不提供模型列表接口时，仍可手动填写服务要求的模型名。
- 无鉴权的本机/局域网服务可以将 `WY_INTENT_API_KEY` 留空，不发送 Authorization；开启鉴权时填服务实际密钥。公网服务仍要求配置密钥。
- 配置新地址且未设置模型名时默认为 auto，也不会自动复用旧 DeepSeek 密钥；新地址默认不发送 json_mode 或 thinking 扩展参数，按服务能力显式启用。
- 改成其他服务前检查 `.env` 中已有的 MODEL、JSON_MODE、THINKING 等选项；显式填写的选项不会自动覆盖。
- 可选变量包括 `WY_INTENT_BATCH_SIZE`、`WY_INTENT_SEED_COUNT`、`WY_INTENT_MAX_TOKENS`、`WY_INTENT_TIMEOUT_SECONDS`、`WY_INTENT_TEMPERATURE`。`.env.example` 提供可复制示例。

新建任务时重新读取生成配置；进行中的任务保持启动时的配置。续跑旧任务仍会校验服务、实际模型名及参数一致。修改 .env 后刷新页面查看配置。

兼容旧配置：未设置 WY_INTENT_* 变量时，继续读取原 JSON 配置及其 `api_key_env` 指定的密钥变量。

## 按你的 JSON 生成 1000 条

1. 新建项目，例如“北斗大模型训练数据”。
2. 点击“添加场景”：场景名称填写“北斗大模型项目意图识别”，场景标识填写 `dam_intent`。
3. 生成要求填写业务范围、表达风格和答案要求。例如“扩写大坝安全监测问句，覆盖口语与专业表达，依据 instruction 输出全部适用标签”。
4. 选择“JSON / 文件导入”，粘贴完整 JSONL 或选择外部文件；也可选择“表格填写”，按字段逐项输入参考样例。
5. 核对解析条数，展开完整预览检查所有字段和识别出的类型，尤其确认 `system` 没有遗漏。错误会显示具体条目或行号，不能当作普通文本继续保存。
6. 提供 4–100 条不同的参考样例后，点击“开始推断标签”。大模型根据完整样例和生成要求判断是否为分类任务并推断标签。推断完成前不能编辑标签或保存场景，运行中锁定场景表单；完成后请人工核对，可输入新标签并按回车添加，也可删除标签。非分类任务可保持空标签。
7. 推断任务会保存当前草稿。可以关闭页面，下次从左侧“标签推断任务”打开草稿与结果，然后保存场景和项目配置。失败或服务重启中断的任务需在任务列表手动重试；关闭浏览器不会取消后台任务。修改参考样例或生成要求后必须重新推断。任务草稿是开始推断时的快照，之后的手动修改仍需保存配置；旧版本草稿不能覆盖已更新的项目。
7. 计划新增数量填写 **1000**，点击“保存场景”，然后“保存配置”。
8. 进入“样本生成”，点击“按配置开始生成”。默认每批从用户提供的 n 条参考样例中选取 3 条，生成最多 10 条。优先选择历史使用次数少的样例，同等条件下随机选择并尽量避开上一批；批次参考编号保存在数据库中，暂停续跑后继续按历史均衡抽取。每次请求独立，不持续追加历史生成内容。1000 条至少需要 100 次请求，过滤重复或无效记录后可能更多。
9. 查看任务进度，支持暂停、继续和停止。失败时保留已完成批次；关闭页面不会停止服务器中的任务。再次点击按配置生成会创建新的新增任务，不是补齐原目标；继续未完成任务请使用“继续”。

**数量含义：新增 1000 条训练记录，参考样例不计入，不自动加入训练集。** 若审核全部通过且没有额外手工样本，则导出为 1000 条。删除或驳回后需按场景补生成差额，再审核；导出页显示实际已通过数量。

## 不会写 JSON：表格填写

添加或编辑场景时，点击“表格填写”。首次进入空场景会提供任务指令、输入、答案三个常见字段；这些只是可替换的模板，不限制其他字段。

1. 在“常用字段模板”选择任务指令/输入/答案、带系统提示的问答、question/answer 或多轮 messages 对话。切换模板会提示替换当前样例。
2. 在表格填写每个字段的内容；文本直接输入，数值用数值框，布尔用开关。对话逐条填写角色和内容，可“添加一轮对话”。
3. 需要额外字段时，填写“自定义字段名”，选择文本、数值、布尔、空值或文本数组，再点击“添加字段”。增删顶层字段会同步作用于所有参考样例。
4. 点击“新增样例”填写下一条；使用“当前样例”下拉框切换，也可删除不需要的样例。每个场景保存时需要 4 到 100 条不同的样例。
5. 可随时切换到“JSON / 文件导入”查看或继续编辑生成的 JSON。有效 JSON 也可转入表格填写，保留原字段与内容；无效 JSON 会提示修正，原输入不会被替换。
6. 核对解析提示和完整预览，设置新增数量后保存场景与配置。

从 JSON 导入的嵌套对象、数组也可逐项编辑现有内容。表格的快捷添加面向常用字段；新增复杂嵌套结构仍可通过 JSON 模式完成。同场景结构不一致时，页面显示校验错误并禁止保存。

## 人工审核

列表显示记录摘要、答案摘要、场景、来源和状态，可展开查看完整 JSON。搜索覆盖全部记录字段。

- 编辑器按记录字段动态生成：字符串用文本框、数值用数值框、布尔用开关、对象和数组用 JSON 编辑框。null 保持 null。不能删除字段或改变类型。配置答案标签约束时，识别出的答案字段使用多选框。
- 多标签答案按配置顺序用顿号连接，不把标签组合建成新场景。
- 每次编辑、删除恢复后重新进入待审核；原始完整 JSON 与修改历史保留。
- 通过、驳回、删除支持当前页勾选批量处理。切换筛选、页面或版本会清空选择。
- 相同场景内按记录上下文去重，生成不会复制参考样例。常见答案字段与对话回复会从上下文标识中排除，system 和其他字段参与标识。检测到相同上下文对应不同答案会阻止导出；无法识别答案字段的自定义格式按完整记录去重。
- 模型生成答案仍需要人工核对。格式校验和标签集合校验不能证明业务标注正确。

一键处理：在“数据审核”点击“一键通过全部待审核”，会处理当前版本所有待审核样本，不受分页或筛选限制。已驳回、已删除样本不变，每条审核仍记录日志。“一键审核并导出 JSON”会将审核、冻结数据作为一个事务完成并触发下载；存在冲突、活动生成任务或缺少有效类别时会拒绝，导出失败时本次批量审核回滚。

## 导出与训练

所有待审核项处理完成、没有答案冲突、各场景都有已通过记录后，进入“数据版本”，点击“保存数据版本”。

- “下载 JSON”：直接下载 JSON 数组，完整保留样例对应的字段名、值类型和嵌套结构，不额外添加场景 ID。JSONL 输入也导出为 JSON 数组。
- “下载训练包 ZIP”：包含 train.json、dataset_info.json、reviewed_samples.json、manifest.json；不同场景需要不同训练映射时，会额外生成分场景的 train_N.json。

新流程完整保存每条记录，包括 system 与其他附加字段。冻结版本保存数量和文件校验摘要，后续修改审核记录不会修改已导出的文件。

标准 `instruction/input/output/system`、`question/answer/system`、`prompt/completion` 自动识别为文本训练格式；`messages`（role/content）和 `conversations`（from/value）自动识别为标准对话格式，支持系统消息与交替用户/助手对话。

自定义字符串字段可展开场景中的“训练字段映射”，选择“自定义文本字段”，指定问题、答案及可选的附加输入、系统提示。字段无需改名；导出的 dataset_info.json 指导原生 LlamaFactory 读取原字段。额外元数据保留在 JSON 中，但不会自动作为模型输入。

无法自动识别或映射为原生训练格式的记录，仍可生成、审核和下载完整 JSON，页面会说明不能直接训练。工具调用、多模态、偏好对等特殊训练格式尚未建立自动映射；需要单独适配，不能仅靠改字段名启动。

完整 LlamaFactory WebUI 的“意图分类”页嵌入同一工作台。选择已保存版本及顶部模型，点击“使用内置参数开始微调”，继续由原 Runner 执行。也可将 ZIP 解压后在 Train 页选择数据目录及 dataset_info.json 中注册的数据集（单一映射为 `wy_intent_train`，混合格式可能有多个）。原训练算法、模型加载和评测执行逻辑没有改写。

轻量工作台不加载训练模型。真实微调需要目标机器上的模型、训练依赖和合适的显存。原有评测指标不能替代多标签任务的集合准确率、Micro/Macro-F1；请准备独立测试集。不得把保留用于最终评测的数据同时用作扩写参考样例。

## 旧工作区

数据库进行添加字段的兼容迁移，保留原项目、样本、审核记录和导出文件。旧版文本类别会在场景卡片上标注“旧版文本配置”。编辑并提供完整 JSON 样例、保存配置后创建新版本，不会把旧的单标签数据默默转换成多标签数据。

## 显示原生训练和评测页面

轻量模式只加载数据工作台。侧栏“模型训练”“模型评测”会说明当前模式及完整模式启动方法。安装完整训练环境后，停止轻量服务，在同一项目目录执行：

```powershell
python -m pip install -e .
python scripts/intent_workbench.py --full
```

默认访问 http://127.0.0.1:7861/ ，可见 Train、Evaluate & Predict、Chat、“意图分类”、Export。`--host`、`--port`、`--data-dir`、`--config` 在两种模式均可使用；同一个数据目录只能由一个服务进程使用。完整模式需要模型训练依赖及可用的基座模型；远程生成 API 不替代训练环境。

在完整界面的“意图分类”页中，工作台侧栏训练/评测入口可以切换到对应的原生标签。使用已审核数据时，在工作台下方刷新并选择已保存数据版本，点击“将数据填入训练页”；会填入数据目录、数据集名称和 LoRA 预设，然后切换 Train。该操作不启动训练，可先核对模型与参数。也可以使用已有的“使用内置参数开始微调”按钮直接启动原 Runner。

原生训练页显示进度、日志、损失曲线及输出目录；Evaluate & Predict 页选择独立测试数据、模型和检查点后执行评测或预测并查看结果。没有把训练数据自动当作独立测试集。原模型加载、训练算法和评测执行仍由 LlamaFactory 提供。


## LoRA 参数与迁移训练

在左侧“模型训练”选择已审核并导出的数据版本，填写目标机器的基座模型路径或模型仓库 ID，并选择匹配的模型模板。模型模板从本项目注册表读取；生成 API 地址或服务名不能代替可加载的训练模型。

开放参数：LoRA Rank（默认 8）、Alpha（空值按 Rank × 2）、Dropout（0）、目标模块（all）、学习率（5e-5）、轮数（3）、每设备批大小（1）、梯度累积（8）、最大序列长度（2048）、精度（auto）、验证比例（0）。固定 SFT + LoRA、不启用量化，其他未暴露项使用 LlamaFactory 默认值和基础运行配置。auto 在运行机器按 CUDA 能力选 bf16/fp16，无 CUDA 时用 fp32。自定义参数不能保证适配任意显存，实际运行时按目标硬件调整。

点击“保存训练配置”，配置会保存在工作区；下次可从“恢复已保存的训练配置”继续使用。修改表单后需要重新保存，下载始终对应保存时的参数和固定数据版本。

### 方式一：迁移包运行

点击“下载 LoRA 训练包”。包含 data/ 下的训练数据与 dataset_info.json、train_config.json、run_training.py、training_plan.json 和 README.txt。配置与数据是一套；数据字段不因训练配置而改变。

在目标机器安装本项目及匹配硬件的 PyTorch 后，解压训练包：

```bash
python run_training.py --dry-run
python run_training.py --model /实际模型路径
```

第一条只展示解析后的参数，不导入训练引擎、不启动训练。第二条使用原生 `python -m llamafactory.cli train` 启动；可从任意工作目录调用启动脚本，数据与输出路径按脚本所在目录解析。也可修改 train_config.json 中的模型、模板和输出目录。包内路径不依赖导出机器的盘符。

默认每轮保存检查点；验证比例大于 0 时每轮计算验证 loss。训练结果位于包内 output/ 下，包括 LoRA 适配器、检查点和原生训练结果/损失图。已有输出目录非空时启动脚本拒绝覆盖，另一次训练请先修改 output_dir。适配器需要配合原基座模型使用；验证 loss 不是分类准确率或 F1。

### 方式二：原生训练界面

在训练机器运行 `python scripts/intent_workbench.py --full`。完整界面顶部先选模型名称（自定义模型可选 Custom），再进入“意图分类”页下方“已保存的 LoRA 配置”，刷新、选择并点击“将 LoRA 配置填入训练页”。这只填入参数，随后在 Train 页核对模型、模板、数据与参数，再点击原生开始按钮。

原生页面沿用自己的训练调度和输出目录规则，默认每 100 步保存/验证，可在原生页调整；迁移包默认每轮保存/验证。进度、日志、损失曲线、终止和后续评测均使用 LlamaFactory 原有功能。仅复制训练包到另一台机器时使用方式一；若要恢复工作台中的配置历史，需迁移对应工作区数据。

完整模式的数据中转：训练数据和独立评测数据都可在“意图分类”页下方选择已冻结的版本并一键填入原生页面，自动携带目录和数据集登记名称。评测填入保留顶部已选模型与适配器；运行中禁止替换参数。评测数据必须由用户另行准备，系统不会把训练数据自动视为独立测试数据。


## 页面路由与删除

工作台使用 #/config、#/generate、#/review、#/versions、#/train、#/eval 路由，地址同时记录项目与数据版本。可直接打开链接、刷新并使用浏览器前进后退，无需给静态服务额外配置路径回退。

已保存场景的删除在确认后立即提交，清理本项目各版本中该场景的配置和样本；当前项目生成新的配置版本，保留其他场景的样本与审核记录，并拒绝旧草稿覆盖。最后一个场景可以删除，之后需要添加场景再生成。未保存的场景只从当前草稿移除。

数据审核的“一键清空样本”永久清理当前版本所有分页、所有状态和回收站中的样本，保留场景参考样例。生成运行中不允许清空或删除，先暂停或停止；对应暂停、失败或中断任务会取消，防止恢复后重新写入。删除操作需确认，不能恢复。已导出的固定数据包不改写。
